# Project Instructions

## Source of Truth

`README.md` is the authoritative project specification.

Always inspect README.md before making substantial changes.

Never assume that existing code fully implements the specification.

## Required Workflow

For substantial tasks:

1. Read the relevant README requirements.
2. Inspect the existing implementation.
3. Determine what is implemented, partial, missing or broken.
4. Plan the required changes.
5. Implement the changes.
6. Verify the implementation.
7. Check that existing functionality was not broken.

## UI/UX

Use the Apple-inspired design skill when performing UI/UX work.

The interface must be:

* premium
* minimal
* spacious
* precise
* consistent
* responsive
* accessible

Avoid:

* generic SaaS dashboard design
* excessive glassmorphism
* excessive gradients
* excessive shadows
* unnecessary cards
* visual clutter

Do not change business logic merely to achieve a visual redesign.

## Architecture

Prefer the existing architecture when it is sound.

Do not rewrite working systems without a clear technical reason.

Use reusable components.

Avoid duplicated logic.

## Security

Backend authorization is mandatory.

Never rely only on frontend visibility to enforce permissions.

Protect student data and private documents.

## Quality

Do not claim a requirement is implemented without verifying it.

Do not create fake functionality when real functionality is required.

Handle:

* loading
* errors
* empty states
* validation
* permissions
* success states

## Final Requirement

The project is considered complete only when the implemented functionality and UI satisfy the requirements described in README.md.
