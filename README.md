# Техническое задание

## Система управления поступлением и сопровождением студентов

---

# Блок 1. Приемка

## 1. Регистрация на сайте

При регистрации на сайте студенту присваивается уникальный ID-номер.

---

## 2. Заполнение личных данных

Студент заполняет личную информацию:

* паспортные данные;
* адрес электронной почты;
* факультет;
* образовательная программа;
* другие необходимые данные.

Также студент загружает фотографию.

Данные должны заполняться поэтапно и быть разделены на отдельные блоки для удобства заполнения.

---

## 3. Загрузка документов

Студент загружает следующие документы:

* Паспорт;
* Аттестат;
* Транскрипт;
* Сертификаты.

### Поддерживаемые форматы

* JPEG;
* PDF.

---

## Формирование документов на основе личных данных

### 1. Application

Заявление автоматически формируется на трех языках:

* казахский;
* русский;
* английский.

Язык формирования зависит от выбранного языка обучения.

### 2. Визовая анкета

Формируется визовая анкета для подготовки приглашения.

### 3. Данные для приглашения

Данные для приглашения предоставляются в виде таблицы в формате Excel.

---

# Блок 2. Отбор

## Этапы отбора

Система предусматривает следующие направления:

* Бакалавриат;
* Магистратура / Докторантура.

---

## 1. Тестирование

Тестирование состоит из двух этапов.

### Этап 1. Профильный тест

Проходной балл:

**65–70%**

### Этап 2. Языковой тест

Для англоязычных групп:

**70%**

Для казахоязычных и русскоязычных групп:

**50%**

---

## Управление вопросами

Вопросы для тестов по темам создаются и загружаются администратором.

Количество тем может составлять до **10 видов**.

Студент проходит профильный тест заранее по выбранной образовательной программе (ОП).

---

## 2. Собеседование

Необходимо предусмотреть расписание собеседований.

Расписание должно содержать:

* дату;
* время;
* информацию о встрече с абитуриентом.

### Ссылки для собеседования

Используются следующие платформы:

* Zoom — для первой группы;
* VooV — для второй группы.

---

## Результаты тестирования

По результатам тестирования определяется проходной балл.

Формируется ведомость с указанием набранных баллов.

Ведомость должна:

* выгружаться в формате Excel;
* отображаться в личном кабинете абитуриента.

---

## Результаты собеседования

Формируется общий протокол собеседования с указанием итогового балла.

Протокол используется для дальнейшей выгрузки в систему **Salem**.

---

## Документы

Расписание собеседований и тестов предоставляется в формате PDF.

---

# Блок 3. Оповещение и последующие действия

## 1. Оповещение студента о результатах

Студент получает уведомление о результатах:

* тестирования;
* собеседования.

Уведомления отображаются в личном кабинете.

---

# 2. Оплата за обучение

Студенту предоставляются реквизиты для оплаты университета.

### Варианты оплаты

* QR-код через Kaspi;
* оплата через банк по реквизитам, указанным на сайте.

### Важно

Подключать систему онлайн-оплаты **не требуется**.

Студент загружает чек об оплате на сайт.

---

# 3. Оплата за приглашение

Студент оплачивает:

**2 500 тенге**

за оформление приглашения через личный кабинет.

Чек об оплате загружается на сайт.

---

# 4. Оплата за медицинскую страховку

Студент выбирает страховую компанию из предложенного списка.

После оплаты студент загружает:

* чек;
* страховой полис.

---

# 5. Заполнение договора

Студент заполняет договор через сайт, используя предложенные поля и пункты.

Номер договора выдается системой автоматически.

Номер договора в дальнейшем используется:

* для формирования приказа;
* для распознавания готового приказа;
* для загрузки приказа в систему.

---

# 6. Подписание и загрузка договора

После заполнения договора:

1. Договор скачивается в двух экземплярах.
2. Студент подписывает договор.
3. Подписанный договор загружается обратно на сайт в личный кабинет.

---

# 7. Загрузка переведенных и нотариально заверенных документов

Студент загружает:

* перевод паспорта;
* перевод аттестата;
* перевод транскрипта.

Данные должны быть представлены на кириллице.

Также студент заполняет ФИО на кириллице в специальных полях.

Эти данные необходимы для дальнейшей работы менеджера и загрузки информации в Excel.

---

# 8. Приказ о зачислении

Система распознает текст приказа.

В том числе система должна распознавать:

* ФИО студента;
* номер приказа;
* дату приказа о зачислении.

После распознавания номер и дата приказа автоматически отображаются в личном кабинете студента.

---

# 9. Уведомление о начале учебы

Студент получает уведомление о начале учебы.

Уведомление включает примерный график занятий для выбранной образовательной программы (ОП).

---

# Блок 4. Приглашение на визу

## 1. Выгрузка приказов

Приказы о зачислении, сформированные в Блоке 3, выгружаются в PDF-формате по номеру файла.

---

## 2. Анкета личных данных

Анкета, заполненная в Блоке 1, доступна для скачивания.

---

## 3. Формирование Invitation Letter

Система автоматически создает приглашение.

Invitation Letter должен содержать:

* фотографию студента;
* необходимые данные студента;
* печать университета.

Формат:

**PDF**

---

## 4. Формирование ходатайства

Система создает ходатайства для подачи в зависимости от страны студента.

---

## 5. Формирование выписки из приказа

Система генерирует выписку из приказа с указанием ФИО студента.

---

## 6. Таблица приглашений

Формируется таблица приглашений в формате:

**Excel**

---

## 7. Выгрузка приказа вручную

Оператор должен иметь возможность вручную загружать приказы через административную панель.

---

# Блок 5. Уведомление о прибытии иностранного гражданина

## 1. Уведомление о прибытии

После прибытия в Казахстан студент уведомляет Визовый офис через личный кабинет.

---

## 2. Заполнение данных о визе

Студент заполняет:

* номер визы;
* срок действия визы;
* фотографию визы / скан.

### Пример номера визы

`№012345678`

### Пример срока действия

`30.09.2024 – 30.08.2025`

---

## 3. Загрузка штампа пограничного контроля

Студент загружает фотографию штампа пограничного контроля.

На штампе должна быть указана дата пересечения границы.

---

## 4. Формирование ZIP-архива

Система формирует ZIP-файл.

ZIP должен включать:

* Excel-документ с данными студента;
* номер визы;
* сроки действия визы;
* фотографию визы;
* фотографию штампа пограничного контроля.

Администратор может скачать ZIP-архив через административную панель.

---

## 5. Адрес проживания

Студент заполняет данные о месте проживания (РКА).

Если адрес проживания изменился, студент указывает новый адрес.

---

# Блок 6. Проживание в хостеле / оформление ИИН

## 1. Проживание в хостеле

Студент может просматривать на карте города партнерские хостелы.

Для хостелов отображается информация о наличии свободных мест.

Через личный кабинет студент может:

* оплатить проживание;
* забронировать место.

---

## 2. Оформление ИИН

В разделе представлена:

* инструкция по получению ИИН;
* адреса соответствующих учреждений.

После получения ИИН студент может добавить его в анкету из Блока 1.

---

## 3. Нострификация

Студент может загрузить файл для нострификации без необходимости посещения офиса.

---

# Блок 7. Рекламно-сувенирная продукция и полезные ссылки

Студенты могут приобрести через данный блок фирменную сувенирную продукцию.

## 1. Общая информация об университете

Раздел включает:

* краткую информацию об университете;

# Административная панель

Административная панель должна поддерживать разные уровни доступа для менеджеров системы.

---

# 1. Главный админ

Главный администратор имеет полный доступ к:

* редактированию всех блоков;
* просмотру всех блоков;
* управлению всеми данными.

---

# 2. Админ Блока 1

Администратор имеет доступ к:

* регистрации;
* личным данным;
* загруженным документам.

Основная задача:

* проверка данных студентов;
* верификация данных;
* работа с документами.

---

# 3. Админ Блоков 2–3

Администратор имеет ограниченный доступ.

Доступные функции:

* загрузка вопросов для тестов;
* внесение результатов тестов;
* редактирование результатов тестов;
* внесение результатов собеседований;
* редактирование результатов собеседований;
* публикация ссылок для Zoom;
* публикация ссылок для VooV;
* просмотр результатов оплаты за обучение;
* просмотр результатов оплаты за приглашение;
* просмотр результатов оплаты страховки;
* выгрузка результатов оплат;
* скачивание договоров;
* скачивание чеков;
* скачивание страховых полисов;
* загрузка готовых приказов по номерам приказов.

---

# 4. Админ Блоков 4–5

Администратор имеет доступ к данным по визовым приглашениям.

Доступные функции:

* скачивание чеков об оплате приглашения;
* формирование отчетности по приглашениям;
* выгрузка отчетности;
* скачивание документов, связанных с приглашением;
* работа с данными уведомления о прибытии.

---

# 5. Интерфейс административной панели

Административная панель должна иметь:

* удобный интерфейс;
* крупный интерфейс;
* список студентов.

---

## Работа со студентами

Администратор должен иметь возможность:

* просматривать студентов;
* редактировать данные студентов;
* сортировать студентов;
* фильтровать студентов.

Фильтрация должна помогать менеджерам управлять большим количеством студентов.

---

# Техническое задание на разработку административной панели

## Цель

Создание административной панели с разделением прав доступа для менеджеров системы в зависимости от их функций и обязанностей.

---

# Требования к функционалу

## 1. Главный админ

Главный администратор имеет полный доступ к:

* редактированию всех блоков;
* просмотру всех блоков;
* управлению всеми блоками;
* настройкам системы;
* созданию аккаунтов других администраторов;
* удалению аккаунтов других администраторов;
* просмотру всех данных студентов;
* редактированию всех данных студентов.

---

## 2. Админ Блока 1 — Регистрация и личные данные

Администратор имеет доступ к проверке данных, введенных студентами при регистрации.

Доступны:

* личные данные;
* загруженные документы.

Администратор должен иметь возможность:

* проверить данные;
* подтвердить данные;
* отклонить данные.

---

## 3. Админ Блоков 2–3 — Отбор и тестирование

Администратор имеет доступ к:

* загрузке вопросов для тестов;
* внесению результатов тестов;
* редактированию результатов тестов;
* внесению результатов собеседований;
* редактированию результатов собеседований;
* публикации ссылок для тестов;
* публикации ссылок для собеседований;
* Zoom;
* VooV;
* просмотру результатов оплаты;
* выгрузке результатов оплаты;
* скачиванию договоров;
* скачиванию чеков;
* скачиванию страховых полисов;
* загрузке готовых приказов по номерам приказов.

---

## 4. Админ Блоков 4–5 — Приглашение на визу и прибытие

Администратор имеет доступ к данным по:

* визам;
* приглашениям;
* прибытию иностранных граждан.

Доступны:

* скачивание чеков об оплате приглашения;
* формирование отчетов по приглашениям;
* скачивание документов, связанных с приглашением;
* скачивание документов, связанных с уведомлением о прибытии.

---

# 5. Интерфейс административной панели

Административная панель должна иметь:

* интуитивно понятный интерфейс;
* крупные элементы интерфейса;
* список студентов.

---

## Управление студентами

Должна быть возможность:

* просматривать студентов;
* редактировать данные студентов;
* фильтровать студентов;
* сортировать студентов.

---

## Поиск и фильтрация

Студенты должны иметь возможность сортировки и фильтрации по различным критериям.

Например:

* имя;
* номер ID;
* статус зачисления;
* этап процесса;
* другие предусмотренные системой критерии.

---

# Дополнительные требования

## 1. Безопасность

Система должна обеспечивать:

* аутентификацию администраторов;
* разные уровни доступа;
* разграничение прав;
* защиту от несанкционированного доступа;
* защиту от несанкционированного внесения изменений.

---

## 2. Логирование

Необходимо вести логирование действий администраторов.

Логи используются для отслеживания изменений в системе.

---

## 3. Скорость работы

Система должна быть оптимизирована для работы с большими объемами данных студентов.

---

## 4. Массовые операции

Необходимо поддерживать массовые операции.

Например:

* массовая выгрузка документов;
* работа с несколькими студентами одновременно;
* другие операции, необходимые для управления большим количеством данных.

---

# Требования к дизайну

## 1. Адаптивный интерфейс

Система должна быть доступна для работы:

* на десктопных устройствах;
* на мобильных устройствах.

---

## 2. Простота и удобство использования

Интерфейс должен быть максимально простым и удобным.

Необходимо минимизировать количество шагов для выполнения основных действий администратора.
